# 前端版本 1、2 的本地运行

按用户 2026-10-19 的选择，当前本地环境使用 **10 月 18 日主站恢复快照的独立持久副本**。版本 1、2 共用原站账号、内容、文件、权限和管理服务。本机修改保存在这个副本中，不自动同步线上，也不改写原快照。

## 当前环境：主站快照的持久副本

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:4286/v1` | 版本 1：保留的原主站前端，转到 `/original` |
| `http://127.0.0.1:4286/v2` | 版本 2：当前新前端，转到 `/` |
| `http://127.0.0.1:4286/resources` | 新版资源中心 |
| `http://127.0.0.1:4286/account` | 原账号功能的新版入口 |
| `http://127.0.0.1:4286/admin-console/` | 保留的原作者后台 |
| `http://127.0.0.1:4286/__local-test` | 只读环境说明，不公开账号、密码、密钥和私有路径 |

已经完成初次准备后，在 `D:\博客` 使用 Node.js 24.21.x 重启：

```powershell
& '.\.local\runtime\node-v24.21.0\node-v24.21.0-win-x64\node.exe' .\scripts\preview-local-frontends.ts
```

这条命令重新构建前端，使用已有 `.local/frontend-versions` 私有配置和数据；不会重新造一份测试数据库。不要使用下面的合成数据启动器替代它。停止时在启动终端按 `Ctrl+C`，再次运行同一条命令即可。端口被占用会退出，不会终止别的程序；`4285` 视觉演示继续保留。

初次准备必须显式传入 `--prepare` 和备份目录。启动器先将清单内容只读复制到暂存副本，再复用原恢复工具校验全部 SHA-256，拒绝覆盖已有配置或数据库。日常重启不需要再次准备。

- 原有密码、作者身份、会员和账号策略保留；使用自己原有的账号密码在本地登录。下面合成测试账号不属于这份主站数据。
- 按用户要求，另在当前本地副本新增 `local-reader@example.test`（普通）与 `local-vip@example.test`（30 天 VIP）两个独立验收读者，凭据已单独交给用户；两版均可使用，重启保留。不新增测试作者，也不重置原账号密码。这两个邮箱与下方一次性合成环境的账号不同。
- 保留原 Tianai 登录验证，启动独立的本机 Java 验证服务；不伪造验证成功、不自动解验证码。
- 本地禁用 SMTP，不发真实注册、验证和重置邮件。因此不能把本地未发送的邮件流程说成已经验收可用。
- 本地禁用独立社区桥接，不连接线上社区；也不启动读者留存清理任务。
- 只监听 `127.0.0.1`，不要把该本机副本转发到公网。快照不是实时生产同步。
- 新版未迁移的公告、音乐、天气等仍保留原业务源码与原界面；不能把两版共用服务理解为新版 UI 已逐项覆盖所有旧功能。

## 另一个用途：隔离的合成数据回归环境

以下启动器仅供开发回归使用，**不是当前主站快照副本的启动命令**。它会创建一次性的合成账号、内容和文件，与上面的持久环境不同；默认端口同为 `4286`，两者不能同时占用。

### 启动与重启

在仓库根目录 `D:\博客` 打开终端，使用 Node.js 24.21.x 执行：

```powershell
node scripts/preview-frontend-integration.ts
```

当前电脑也可以直接使用已经准备好的 Node，无需修改系统环境：

```powershell
& '.\.local\runtime\node-v24.21.0\node-v24.21.0-win-x64\node.exe' .\scripts\preview-frontend-integration.ts
```

启动会构建原站界面、原作者后台和新版前端，再建立本次专用的测试数据库。终端出现“新版前端本地联调”后，即可访问：

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:4286/` | 新版界面，与原站服务同源 |
| `http://127.0.0.1:4286/account` | 原账号功能的新版界面 |
| `http://127.0.0.1:4286/original#/home` | 保留的原版界面 |
| `http://127.0.0.1:4286/admin-console/` | 原作者后台 |
| `http://127.0.0.1:4286/__local-test` | 测试账号与操作说明 |
| `http://127.0.0.1:4286/__local-test/mailbox` | 本次注册和重置密码邮件的本地捕获结果 |

在启动终端按 `Ctrl+C` 正常停止，再执行同一条命令即可重启。每次重启都会创建一份全新的测试数据，之前的测试会话、修改和捕获邮件不会保留。正常退出会先关闭服务器和数据库，再清理本次临时目录。

如果端口已经被占用，启动器会报错退出，不会自动终止其他程序。不要同时运行两份启动器；先回到原启动终端停止现有进程。已有的 `4285` 视觉预览不用停止，本启动器不会修改其监听进程。

### 合成测试账号

统一密码为 `DemoLogin2026!`：

| 邮箱 | 身份 |
| --- | --- |
| `reader@example.test` | 普通读者 |
| `vip@example.test` | 有效 VIP |
| `expired@example.test` | 会员已过期 |
| `owner@example.test` | 作者 |

使用原站真实的密码校验、会话、发布、撤回、上传、下载、会员权限、章节读取、验证码注册和密码重置服务。作者登录后可以进入原后台测试发布；新版与原版共用本次本地服务的 Cookie。

读者仍遵守原站每个 IP 的账号登录数量限制。反复切换超过三个不同读者账号可能被拒绝；这不是前端切换失败。浏览器测试普通、VIP 和过期会员时，直接使用表中这三个读者账号即可。

### 合成环境边界

- 数据来自 `scripts/fixtures/frontend-integration.ts`，只含可识别的合成账号、测试内容和测试文件；其中的普通书籍和 VIP 书籍均有三个章节，文章有独立的公开附件。
- 本次临时数据放在新建的 `.local/frontend-integration-随机值/data` 下。本启动器不会读取私有运行配置，不复制既有数据库，不连接线上数据库，也不改动生产内容、读者、VIP 或上传文件。
- 注册与重置邮件只捕获到本次进程内存，不向真实邮箱发送。建议使用 `名称@example.test` 测试。
- 登录滑块没有注入到本地测试服务。原接口返回 `{ "enabled": false }`，不提供虚假的验证成功结果；这不等于已经验证生产环境的验证码或反滥用能力。
- 只监听 `127.0.0.1`，请求还会检查本地来源和 Host。不要把这个测试服务转发到公网。
- 启动器只调用现有构建与业务模块，不更换视觉方案或第三方组件。新版资源来自正常构建结果，后端没有另造业务 API。

详细前端功能映射和验收记录见 [新版前端接入说明](../previews/hero-upgrade/LOCAL-INTEGRATION.md)。

## 自动回归

从仓库根目录运行真实 HTTP 集成测试：

```powershell
node --test tests/frontend-integration-preview.test.ts
```

该测试自行选择空闲本地端口，创建独立临时数据，验证后关闭并清理，不占用正在验收的 `4286`。

验证前端 bootstrap、身份刷新、发布时间、详情取消与旧 hash 路由转换：

```powershell
node --test previews/hero-upgrade/tests/integration-runtime.test.mjs
```

自动测试通过代表这些契约已验证，页面的视觉质量和生产上线配置仍按实际验收结果判断。

## 与正式替换的区别

本页两个启动器仅用于回环地址的本地验收。正式版本 2 已有独立源码构建和可选入口，默认仍是版本 1；明确的源码清单、依赖安装、统一完整性校验及 `SITE_FRONTEND` 选择见 [可选前端交付说明](FRONTEND-DELIVERY.md)。正式入口复用原私有配置与持久业务服务，不复用本地测试标记或快照配置。
