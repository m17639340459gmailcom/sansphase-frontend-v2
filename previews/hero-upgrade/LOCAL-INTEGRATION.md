## 实现边界

1. 内容查询复用 `src/content-reader.ts`、原 `contentQuery` 和 `server/content-delivery.ts`，没有增加另一套业务接口。登录、VIP、上传和发布仍交给原服务。
2. 目录仅接收有界摘要字段。正文、附件清单、稳定记录 ID 和作者身份不会混进目录 DTO；详情与章节按需读取。
3. 媒体保持同源 `/api/media/<UUID>`，没有改成 `/media`，也没有把生产私有文件转成公开图片代理。下载只能使用原下载 URL；外链仅接受 HTTP/HTTPS，不接受凭据式 URL。
4. 本地模式不能切回示例数据。401、403、网络错误与空内容有不同提示，失败不会显示一组假内容让人误以为已经连接成功。
5. 查询、翻页、路由离开和身份变化有取消与代次校验。旧请求晚到时不能覆盖新页面，也不能把退出前的受限内容继续留在可见页面。
6. 现有资料、软件与资源中心首幕继续使用已确认的组件和动效；联调只替换数据和链接。没有为本次功能适配增加新的渲染框架、特效引擎或生成素材。

### 加载检查的具体含义

隔离详情适配前观测到首个入口静态依赖为 452,961 raw bytes。拆分模型并改为本地按需加载后观测为 **437,786 raw bytes**；当前 `loading-architecture` 的既有 **450,000 raw bytes** 上限通过。数字会随后续源码变化，最终以构建测试为准。没有把改大预算当作优化结果。

这里只是构建依赖体积，不是首屏下载量或加载秒数。生产加载还受到字体、图片、缓存、网络、CPU/GPU 和数据规模影响；本地不能证明真实网络下的速度。哈希静态资源、按需 Reader/3D/图片查看器、压缩偏好与 `q=0`、HTML 重验证和私有 API `no-store` 均有对应加载回归。

## 尚不能作出的交付声明

- 不能说“所有原 UI 功能一一迁移完成”：公告、音乐、天气、实际社区流程还未进入新界面；部分首页品牌/联系字段仍是预览内容。
- 不能说“所有历史内容和账号操作已逐项验收”：当前主站快照副本已接入，但所有历史链接、长标题、超长正文、附件类型以及登录后的每项内容还需独立核对。
- 不能说“已经达到生产安全验收”：当前本地保留真实 Tianai 验证码，但尚未完成真实邮件发送、生产验证码部署、真实域名 Cookie/TLS、反向代理与生产运维验收。
- 不能用接口与 DOM 测试替代视觉验收：桌面明暗主题、3D 书本、鼠标反馈、图片弹层、完整账号操作和字体加载仍需在正在运行的本地界面实际走一遍。
- 不能把这次分支或预览构建直接当发布包。正式切换应依照仓库维护约定，从明确源码清单执行 `release:prepare`，完成回滚方案并获得当次发布授权。

当前可交付的是：保留原视觉版本，同时提供一个可在本机验证原账号、VIP、已发布内容、附件和原书籍 Reader 的独立新前端环境。原业务模块与管理入口继续保留，为后续更换前端提供兼容层。
